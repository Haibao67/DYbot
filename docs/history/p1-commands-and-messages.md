# P1：中文指令与消息输出

## 最初计划

在 P0 原生引用回复之上增加铃露中文指令入口、兼容旧命令，并统一帮助、菜单、牧场与交易消息的排版。计划要求继续使用 Core + Browser Worker，不把尚未开放的 P2–P5 玩法伪装成可用功能；业务数据由服务计算，展示层只格式化。

## 实际实现及演进

- `command_router.py` 将 `/铃露玩法`、`/菜单`、`/牧场`、`/买动物`、`/喂食`、`/收取`、`/行情` 等入口映射到现有用例；`/牧场 查看` 等旧形式保留。后续阶段的 `/加工厂`、`/投产` 等命令是逐阶段接入，并非 P1 一次上线。
- `presentation/messages.py` 保留兼容入口，`presentation/ruihe.py` 与 `formatters.py` 承担标题、数量、货币、剩余时间、进度条等格式。牧场面板从最初的逐动物展示演进为同类汇总及状态展示；2026-09-26 已部署紧凑格式，隐藏零库存/零饲料行。
- 所有玩家主动指令及错误回复继续引用各自原消息。后续平台拒绝长消息时采用明确拒绝后按行拆分，拆分段继续引用原消息；主动公告不引用玩家。
- 后续本地修订重新分组 `/帮助`，并将出售提示写成明确的商品和数量。这些本地修订截至整理日尚未部署。此前给每条发送内容附加的 `---HH:mm:ss---` 已在本地发送层移除，服务器最新已验证包仍保留该旧行为；业务时间与协议时间保留。

## 数据、验证与发布

P1 无单独 Alembic 迁移，依赖 P0 的 `0003_reply_context`。P0/P1/P2 曾作为已提交版本发布，维护手册保留当时发布记录；没有独立可核对的 P1 专项发布 ID。2026-09-26 牧场紧凑面板发布 `5a4e915be7e6-20260926-223000`，当时本地与服务器相关全套各 106 项通过。上述后续本地文案修订曾做定点 90 项；本轮档案整理没有重新测试。

## 保留问题与来源

网站手动 Socket ACK 已确认 `content.reference.{id,sentBy,content}` 结构可被接受；客户端原生引用 UI 的人工目视验收仍按 [开放问题](../ruihe-open-questions.md) 记录。详见 [阶段计划 P1](../ruihe-codex-plan.md)、[进度](../ruihe-progress.md) 和 [维护手册](../update-maintenance-guide.md)。
