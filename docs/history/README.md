## 阅读口径

- 每份档案区分“最初计划”“实际实现”“后续修订”“验证/发布”“保留问题”。计划中的功能不能据此视为已经上线。
- P0 原生引用回复是上述阶段共用的基础；P5.5/P6A、群邀请、回复效率 5.5A–C 属于后续阶段，不并入 P1–P5 的验收范围。
- 本地 Git 工作区含大量尚未提交的后续改动。2026-09-27 最近验证的服务器发布为 `5a4e915be7e6-20260927-164155`（迁移 head `0012_outbound_scheduler`）；本地新增的牧场/行情/加工厂/帮助文案修订及回复末尾时间标记移除**未部署**。不能仅凭 Git 提交号重建曾以工作区包发布的版本；需同时核对发布包 SHA256 与维护记录。
- 规则权威来源为 [参考规则](../reference/ruihe.md)、[阶段计划](../ruihe-codex-plan.md)；实际完成与开放问题以 [开发进度](../ruihe-progress.md)、[开放问题](../ruihe-open-questions.md) 为准。部署与可恢复备份见 [维护手册](../update-maintenance-guide.md)。本目录不替代这些仍在维护的文件。
- 档案依据上述本地资料和本轮只读源码核对编写；没有重新运行测试、连接服务器、访问正式数据库或发送群消息。历史测试数字沿用当时记录，不表示本轮重新验收。

## 基线与阶段边界

最初提交 `e5b1f4f` 建立 Core/Worker 游戏平台。P0 将玩家原消息 ID 和内容贯穿 Core、outbox 与 Worker，通过 Socket `content.reference` 原生引用回复；迁移为 `0003_reply_context`。P1 在此基础上完成玩家可见指令与排版。P2–P5 保留既有身份、余额、库存、账本、outbox 和 Alembic 历史。P5 的一次工作区发布将 `0004` 至 `0007` 一并部署，因此阶段实现顺序与服务器发布次数并非一一对应。
