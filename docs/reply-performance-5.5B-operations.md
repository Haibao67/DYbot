# 5.5B Socket 自适应节流操作说明

状态：2026-09-27 曾按全局 2 秒、同一私聊 5 秒配置部署。2026-09-29 本地默认值已调整为全局初始/最小间隔 1 秒，尚未部署或进行真实平台试验；正式环境配置状态仍以本轮只读检查为准。未经授权的正式群不发送合成测试消息。

## 安全默认配置

在 Worker 环境中设置以下变量。正式服务器现有环境文件缺少这些变量时自动使用默认值；无效值会使启动明确失败。

| 变量 | 默认 | 单位与说明 |
| --- | ---: | --- |
| `DZMM_SOCKET_INITIAL_INTERVAL` | 1 | 秒，全局启动间隔 |
| `DZMM_SOCKET_MIN_INTERVAL` | 1 | 秒，连续成功自适应降速的下限 |
| `DZMM_SOCKET_MAX_INTERVAL` | 60 | 秒，明确限流后的退避上限 |
| `DZMM_SOCKET_PRIVATE_INTERVAL` | 5 | 秒，同一私聊最小间隔 |
| `DZMM_SOCKET_SUCCESS_WINDOW` | 30 | 次，连续成功 ACK 数达到后降低一档 |
| `DZMM_SOCKET_SUCCESS_STEP` | 0.1 | 秒，每档降低量 |
| `DZMM_SOCKET_RATE_COOLDOWN` | 60 | 秒，明确限流后暂停；outbox 的 60 秒 retry 规则不变 |
| `DZMM_SOCKET_BACKOFF_FACTOR` | 2 | 倍，明确限流时提高当前间隔 |

只有平台 ACK 明确包含现有“请稍后再试”限流提示时才退避；普通拒绝、未知 ACK 和传输超时都不计为成功证据。长消息拆出的每一段经过同一限速器。Worker 重启后从 `INITIAL_INTERVAL` 重新开始，不恢复进程内自适应状态。Bot HTTP 主动公告保持原实现。

管理员 `GET /admin/performance` 中的 `limiter` 来自 Worker 心跳，包含当前间隔、最近限流 UTC Unix 秒、限流次数、调整次数、连续成功数和剩余冷却秒数。`limiter_stale=true` 时勿用其判断当前发送速度。5.5A 的队列及 ACK 分位数仍按原口径查看。

## 本地固定时钟对比

在同一批任务同时排队、平台调用耗时设为 0、且固定全局间隔的假负载下：

| 任务数 | 2 秒 P50/P95 等待 | 1.5 秒 P50/P95 等待 |
| ---: | ---: | ---: |
| 10 | 8 / 18 秒 | 6 / 13.5 秒 |
| 100 | 98 / 188 秒 | 73.5 / 141 秒 |
| 500 | 498 / 948 秒 | 373.5 / 711 秒 |

这只验证限速器计算与队列模型，不代表真实平台吞吐。真实平台可能对更短间隔限流；1 秒配置需在授权测试群观察成功 ACK、明确限流、failed、uncertain 和 P50/P95。若限流或失败明显增加，把 `MIN` 与 `INITIAL` 恢复为 2 秒并重启 Worker，随后核对 Core/Worker 健康和队列状态。
