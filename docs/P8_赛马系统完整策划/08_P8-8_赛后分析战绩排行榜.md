# P8-8 · 赛后分析、战绩、奖金与排行榜

> **目标：让比赛结果反向指导培养，让每匹马形成长期可展示的赛事履历。**

---

# 1. RacePerformance

每匹参赛马保存：

```text
race_id
horse_id

final_rank
finish_gap

stamina_start
stamina_finish

overtake_attempts
overtake_successes

blocked_count
block_avoided_count

skills_triggered
skills_failed

key_events
analysis_snapshot
created_at
```

---

# 2. 赛后分析目标

赛后报告回答四件事：

```text
哪里表现好？
哪里丢失优势？
哪些属性真正发挥？
下一步适合培养什么？
```

---

# 3. 示例

```text
—— 📊 星河 · 赛后分析 ——

最终：第2名

✅ 中距相性 S
本场距离发挥优秀

✅ 差跑法相性 S
中后程位置控制稳定

✅ 智慧 811
成功避开2次拥堵

⚠️ 耐力 618
最后300m仅剩8%体力

🔥 毅力 663
帮助它在低体力状态保持冲刺

主要失分：
最后直线最高速度略低于冠军

推荐培养：
⚡速度
🫀耐力
```

推荐只根据本场数据解释，不强行告诉玩家唯一最优方案。

---

# 4. 技能分析

```text
—— ✨ 技能表现 ——

【弯道加速 Lv9】
✅ 发动1次
最终弯道获得明显加速优势

【冷静换道 Lv5】
判定2次
成功1次
失败1次

【末脚 Lv4】
✅ 最后直线发动

【强健体魄 Lv3】
持续生效
减少了部分体力消耗
```

---

# 5. 分析必须来自真实事件

不要根据最终名次硬生成套话。

例如：

```text
blocked_count == 0
```

就不能说：

```text
“因为智慧高成功避开两次拥堵”
```

分析必须基于 `RaceEvent` 和 `RacePerformance`。

# 7. 战绩字段

可保存聚合：

```text
HorseRaceRecord

horse_id
starts
wins
seconds
thirds
prize_total
season_points
updated_at
```

比赛详细历史仍从 RaceEntry / RaceResult 查询。

---

# 8. 奖金

P8 第一版奖励：

```text
冬宴币
荣誉
称号
赛季积分
未来技能奖励接口
```

禁止普通赛事直接大量增加五维。

---

# 9. 奖金结算

同一事务：

```text
RaceResult
+
ledger
+
player balance
+
HorseRaceRecord
```

账本原因：

```text
race_prize
race_entry_refund
```

---

# 10. 发奖幂等

每个：

```text
race_id + player_id + prize_type
```

必须唯一或有等价幂等键。

重复 Worker 不得重复发奖。

---

# 11. 排行榜

建议：

```text
/排行榜 赛马
```

提供独立榜单：

```text
冠军数
总奖金
赛季积分
```

不要做一个难以解释的“综合战力榜”。

---

# 12. 赛季排行榜接口

即使暂时不做赛季重置，也预留：

```text
season_id
```

避免以后排行榜只能做永久累计。

---

# 13. 马匹荣誉

未来：

```text
首胜
三连胜
某大型赛事冠军
长距王
泥地王
年度马王
```

P8-8 可先建 `HorseAchievement` 接口，不必填满成就。

---

# 14. 世界动态

只广播：

```text
首次冠军
重大赛事冠军
高代血统首胜
连胜纪录
破纪录
```

普通赛事不广播，避免刷屏。

# 16. `/待办`

```text

/战绩 星河
```

不重复提醒。

# 18. 验收标准

- 赛后报告可解释；
- 奖金正确到账；
- 战绩正确累计；
- 技能发挥可查看；
- 排行榜可查询；
- 重复结算不重复发奖；
- 分析内容与真实 RaceEvent 一致。
