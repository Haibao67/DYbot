# P8-1 · 马匹数据结构升级与相性系统

> **目标：在不破坏 P6 马匹数据的前提下，引入距离、场地、跑法三类相性。**

---

# 1. 交付内容

每匹马新增：

```text
距离：短距 / 英里 / 中距 / 长距
场地：草地 / 泥地
跑法：逃 / 先行 / 差 / 追
```

等级：

```text
S / A / B / C / D / U
```

`U` 表示尚未补定，不是 D。

---

# 2. 推荐数据模型

优先使用独立表：

```text
HorseAffinity

horse_id
category
key
grade
source
generation_version
finalized_at
```

category：

```text
distance
surface
running_style
```

key：

```text
short / mile / medium / long
turf / dirt
front / stalker / mid / closer
```

唯一约束：

```text
UNIQUE(horse_id, category, key)
```

---

# 3. 为什么独立表

- 后续增加新相性无需继续扩 Horse 主表；
- 遗传可统一处理；
- 历史快照更简单；
- P7A 拍卖展示方便；
- Race Engine 只通过 Resolver 读取。

---

# 4. 老马迁移

迁移只新增结构，不改现有：

```text
五维
成长等级
繁育次数
父母
代数
```

历史马相性初始为 `U`。

第一次需要相性时：

```text
finalize_affinity()
```

确定性 seed：

```text
hash(horse_id + affinity_generation_version)
```

要求：重复请求、服务重启、事务重试都不能改变结果。

---

# 5. 新购 G0

创建时直接生成相性。

概率不要写死，统一进入：

```text
g0_affinity_weights
g0_affinity_guarantees
```

建议保底：

```text
至少一个距离 >= B
至少一个跑法 >= B
草地/泥地至少一个 >= B
```

---

# 6. 相性作用接口

建立：

```text
AffinityResolver
```

输入：

```text
horse_id
race_distance_type
surface
running_style
```

输出：

```text
distance_grade
surface_grade
running_style_grade

distance_modifier
surface_modifier
running_style_modifier
```

# 9. 版本化

保存：

```text
affinity_generation_version
```

未来调整概率：老马不重算，新马走新版。
