# 铃露每日天气规划与实现记录

> 状态：2026-09-29 已部署并启用；生产环境 `DZMM_WEATHER_ENABLED=true`。使用香港时间和全服唯一日天气，主动公告经 outbox/Worker 发送。其他新环境仍默认关闭，避免未授权时自动广播。
>
> 依据：项目既有天气约定——天气按全服日期统一、结果可复算并持久化；牧场效果见 `docs/ruihe-codex-plan.md`，农场效果及关闭状态见 `docs/ruihe-open-questions.md` 与 `docs/ruihe-progress.md`。
>
> 规则边界：本文规则与主动群公告策略经用户确认；生产部署及启用已经授权并完成。部署和验收事实详见 `docs/update-maintenance-guide.md`。

## 1. 规划目标

每日天气为全服牧场与农场提供同一份、稳定可查的环境状态。目标包括：

- 同一游戏日期的所有玩家看到相同天气，不因查询时刻、玩家或进程实例不同而变化。
- 每日只产生一个权威天气结果；Core 重启、任务重试或多实例竞争不得重抽或重复结算。
- 生产计算使用明确版本的天气定义与效果，历史生产结果不受未来规则修改影响。
- 玩家能在相关面板看到当天环境及实际生效效果；天气停用时明确显示未启用，不显示伪造天气。
- 天气是轻量环境层，不擅自改变动物喂食、农作物成熟时间、市场价格或赛事规则。

## 2. 当前规则基线

### 2.1 已确认天气效果

正值表示有对应概率增加产量基数；负值表示有对应概率减少产量基数。例如 `-30%` 表示有 30% 概率减少 1 个基数单位。牧场按同一种动物每天判定一次，农场按每块田分别判定，细则见第 3.4 节。

| 天气 | 牧场效果 | 农场马粮作物 | 农场经济作物 |
|---|---|---|---|
| 晴天 | 全部动物 +50% | +50% | 无效果 |
| 雨季 | 羊毛 +80% | 无效果 | +50% |
| 旱季 | 鸡蛋 -30% | -50% | -50% |
| 闷热 | 牛奶 -30% | +20% | 无效果 |
| 微风 | 无效果 | 无效果 | +20% |
| 丰收祭 | 全部动物 +150% | +150% | +150% |

### 2.2 已知但尚不能视为完整规则的事项

- 五种普通天气各 19%，丰收祭 5%，总概率 100%。本轮先前消息中的 18%/10%被后续明确的 19%/5%取代。
- 天气效果是增减产出基数单位的概率，不再采用倍率乘产出后四舍五入的旧表述。普通生产的既有基数计算仍照常进行。
- 牧场同一种动物的增减产天气判定每天只进行一次；该动物类型调整后的产量基数乘以该类型动物数量。
- 农场每块田各自进行天气判定；每块田的基础产量基数由作物种类决定。
- 增产概率按百分数拆分：每满 100% 保证增加 1 个产量基数，余数部分再按对应概率额外增加 1 个基数。例如 +150% = 保证 +1，另有 50% 概率 +1。
- 当前所有植物的基础产量基数均为 1；规则按植物种类分别配置，以支持未来逐种调整。
- 农场天气按收获日判定。作物跨越香港时间午夜成熟时，按实际收获所在游戏日的天气处理。
- 生产数量其他已有取整规则仍适用于其原有步骤；天气概率命中后对整数基数做增减，不另做倍率取整。
- 农场播种快照曾保存天气字段，但目前值为 `disabled`；这不是已启用天气的证据。
- 天气按香港时间每日午夜切换并供牧场、农场共用。天气首次生成、停机补齐及具体业务结算接入仍需落实。

## 3. 核心规则建议稿

以下系统行为是实现建议；标为待确认的细节须由产品确认后才能成为正式规则。

### 3.1 日期、时区与有效周期

- **游戏日时区：** `Asia/Hong_Kong`（香港时间）。
- **有效周期：** 香港时间每日 00:00 至次日 00:00；每日切换一次全服天气。
- 日期键使用游戏日日期，不用服务器本地时区，也不以玩家时区分别计算。
- 天气记录的唯一键为游戏日期；跨午夜后新游戏日使用新天气。
- 当日天气主动广播至 Core 当前启用的群聊，通过现有 outbox/Worker 发送；不私聊、不引用玩家消息。

### 3.2 天气生成与固定

- 系统应为每个游戏日生成且只生成一个天气结果，并在第一次对玩家公开或被生产使用前持久化。
- 生成应由 Core 的可恢复后台调度完成；调度采用唯一日期约束/事务保护，重试只读取已有结果，不重新抽取。
- 若 Core 在日界线之后才恢复，按缺失日期逐日补齐，使用当日配置版本和种子规则生成，不跳过日期，也不把补齐结果套到当前日期。
- 玩家查询、群内并发指令、Worker 重连均不得触发随机重抽。
- 同一日使用独立确定性种子。建议种子输入包含固定命名空间、日期和天气配置版本；不得使用玩家 ID、群 ID或不稳定的进程随机状态。
- 天气配置变化只影响新生成且尚无记录的日期；不得重算已有天气或历史产出。

### 3.3 概率分布

每日概率已确认如下，合计为 100%。

| 天气 | 每日概率 |
|---|---|---:|
| 晴天 | 19% |
| 雨季 | 19% |
| 旱季 | 19% |
| 闷热 | 19% |
| 微风 | 19% |
| 丰收祭 | 5% |
| **合计** | **100%** |

按每天一次全服天气抽取理解。连续同天气允许；概率独立，不设保底、连日限制或重复惩罚。若以后加入季节或事件修正，另行版本化概率配置；当前不加入修正。

### 3.4 作用范围与计算顺序

- 天气是**全服游戏日状态**，不是每群或每玩家状态。
- 天气只修改第 2.1 节明确登记的牧场与农场产出；不直接修改售价、市场行情、动物属性、作物成熟时间、繁育、马匹赛事或加工工时。
- 生产批次应冻结所用天气类型、天气规则版本、概率配置版本及效果，便于审计与复算。
- 建议顺序：先按原有规则算出整数基数产出，再对天气适用的基数单位作增减概率判定，最后进入既有收取/库存流程。
- 正值暂按每个适用单位以给定概率增加 1；负值按用户定义，以给定概率减少 1。天气判定应使用独立、可复算的随机流，不能改变其他游戏随机结果。
- 减产建议最低为 0，不允许负产出；基数为 0 时不判定。该保护规则需确认。
- 牧场每天对每种当前存在的动物类型独立判定一次，得到当日该类型共享的调整后基数；当天该类动物的生产均复用此结果，不重复判定。计算为 `该次该类产出 = 当日调整后基数 × 该类动物数量`。每种动物的默认基数为 1。
- 农场每块已种植田地独立判定一次，调整该植物的产量基数后计入该田产出；同种作物的不同田地也分别判定。基础产量基数由植物种类决定。
- 农场分类按第 4 节清单配置；新增作物不自动归类，须补充天气规则。
- 动物类型当日天气判定结果用于该类动物当日天气产出；农场天气判定按每块田结算。接入时须保证重试不会对同一日/同一田重复抽取。
- 增产概率高于 100% 时，每满 100% 保证增加 1 个基数，余数作为再增加 1 个基数的概率；例如 +150% 为保证 +1、另有 50% 概率 +1。

### 3.5 不生效情形

- 天气总开关关闭、概率配置校验失败或天气定义版本未知时，状态为 `disabled` 或 `invalid_config`，生产继续按无天气修正执行。
- 禁用状态不得随机生成展示用天气，不得将某个天气伪装为“晴天默认”。
- 已有天气记录可继续查询历史；关闭功能不删除记录、不回滚已入账产出。
- 规则实现不得让天气故障阻塞不依赖天气的玩家查询、收取、喂食或其他经济操作。

## 4. 农场规则核对清单

农场效果、两类作物、判定粒度及收获日天气规则已确认。每块田地独立判定；当前所有植物基础产量基数均为 1，并按植物种类分别配置，便于未来调整。

| 天气 | 马粮作物增产概率 | 经济作物增产概率 |
|---|---|---|
| 晴天 | +50% | 无效果 |
| 雨季 | 无效果 | +50% |
| 旱季 | -50% | -50% |
| 闷热 | +20% | 无效果 |
| 微风 | 无效果 | +20% |
| 丰收祭 | +150% | +150% |

马粮作物：牧草、燕麦、胡萝卜、大麦、苜蓿、苹果。经济作物：小麦、向日葵、葡萄、棉花。天气规则调整收获产量基数，不改变成熟时间；跨日作物使用收获日天气。

## 5. 玩家交互与展示

建议命令与展示仅在天气规则确认并启用后开放：

- `/天气`：展示今天的全服天气、有效日期、主要作用和当前规则状态。
- `/今日`：展示天气摘要及对该玩家当前牧场/农场真正适用的效果；不重复堆叠冗长说明。
- `/牧场`、农场面板：展示天气名称与增减产概率说明；若没有相关资产或该天气对其无影响，避免误导性效果文案。
- 天气未启用时显示“每日天气暂未启用”，不显示随机值或无规则依据的预计天气。
- 帮助只列出已实现、已开启的命令。无需为了规划稿提前注册可用命令。

文案需要区分：天气是什么、对当前资产的作用、何时生效、规则版本状态。面向玩家的措辞应简洁，不暴露技术细节。

## 6. 数据与版本建议

此节是实现建议，不是已批准的数据库设计。

### 6.1 每日天气记录

建议增加全服每日天气表（最终命名待实现时确认），至少保存：

- `game_date`：游戏日日期，唯一。
- `weather_code`：稳定内部枚举代码。
- `weather_rule_version`：天气效果规则版本。
- `probability_config_version`：概率分布配置版本。
- `seed` 或安全的 seed 标识：用于重现生成；不得暴露秘密密钥。
- `generated_at`：UTC 时间戳。
- `effective_from`、`effective_until`：UTC 边界，或由日期和固定时区规则可靠推导。
- 可选 `definition_snapshot`：冻结当日天气效果，防止后续配置变更改写历史语义。

天气历史属于运行数据，不可因修改配置而覆盖。若每日结果连同完整定义快照已能复算，可避免重复保存冗余字段；选择需在迁移设计中固定。

### 6.2 生产快照与审计

- 已有农场播种快照里的 `disabled` 状态须保持兼容；启用天气后定义清晰的迁移/首次适用语义。
- 牧场批次若是连续累计，应记录每个计产时点所使用的天气，或采用可精确重建的分段账目；不能只在最终收取时套用“今天”的天气。
- 天气本身不应直接发货或记账。实际收取仍由现有生产/库存/账本事务负责，并记录天气修正依据。
- 管理员调整规则只影响未来配置，不改已生成天气、已结算产出或历史账本。

## 7. 后台运行与运维

- 生成任务由 Core 管理并持久化，不由每个 Worker 各自随机生成。
- 日界线任务必须幂等，并支持服务停机后补齐；启动服务不等于任务已成功，需检查当日唯一天气记录及生成状态。
- 配置发布前校验：天气代码完整、概率非负、总和严格为 100%、效果字段合法、版本号唯一。
- 不依赖正式玩家消息发送天气结果。自动公告若规划为群播，需单独确认发布策略、目标群、失败重试与是否允许静默；天气状态和业务正确性不能以公告成功为前提。
- 若未来向全群公告，应作为无引用主动消息进入现有 outbox，不可引用任一玩家指令。
- 维护面板应能区分：天气记录缺失、配置无效、正常生成、补齐生成、功能关闭；记录错误但不泄漏随机种子秘密或凭据。

## 8. 测试与验收规划

### 规则测试

- 权重总和、负权重、空分布、未知天气代码均有明确拒绝结果。
- 固定日期、种子和配置版本可以复现相同天气；不同日期可独立生成。
- 相同日期并发生成只能落一条记录；重复任务不重抽、不改结果。
- 时区边界、服务器 UTC 与本地时区不同的情况有明确结果。
- 各种天气对每种受影响/不受影响商品应用正确概率；基数调整与最小产出边界有测试。
- 配置版本升级不改历史天气和历史生产快照。

### 状态与故障测试

- 功能关闭、缺失概率、配置合计错误时无天气效果且其他生产可正常进行。
- Core 在日界线前后重启、错过多个游戏日、后台任务重复执行时正确补齐。
- 数据库唯一约束或事务失败时无部分状态；重试可安全恢复。
- 已种植作物、跨天气日界线的动物产出如何处理，按最终确认口径验证。
- `/天气`、`/今日`、牧场和农场长面板均引用对应玩家原消息；主动公告不引用玩家。

### 灰度验收

1. 固定时钟与固定种子的纯规则测试。
2. 临时 SQLite 集成，检查多日补齐、重启和重复调度。
3. 若使用 PostgreSQL，执行迁移副本演练、并发生成和历史数据核验。
4. 功能开关保持关闭部署结构/迁移（若获准），确认旧生产与旧快照无变化。
5. 使用测试群确认面板与实际产出后，才单独讨论启用范围。

测试未执行不得报告通过。上线或启用天气需要另行授权；本文不构成部署授权。

## 9. 实施切片建议

1. **规则闭合**：确认概率、日期时区与边界、农场完整效果表、跨日生产归属、是否有连日约束。
2. **纯规则与配置验证**：天气 Registry、概率校验、确定性选取和增减产概率判定；保持总开关关闭。
3. **每日状态持久化**：新增每日唯一记录与幂等补齐调度；迁移副本验证。
4. **牧场接入**：按已确认游戏日归属天气，冻结概率规则版本和判定结果。
5. **农场接入**：确定播种快照与天气关系，避免回溯改变既有作物。
6. **展示与玩家验收**：天气查询、今日摘要、面板、原生 Reply 和长消息验收。
7. **独立启用决策**：先白名单/测试范围，再按授权扩大；记录真实运行结果。

各切片单独评审和验收；若农场或牧场规则尚未闭合，可先完成不启用生产效果的天气记录框架，但不得展示成已生效玩法。
