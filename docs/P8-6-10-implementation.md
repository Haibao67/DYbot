# P8-6～10 implementation status

2026-09-28：本地开发，未部署。延续用户决定：先完成框架，缺配置的功能关闭。

## P8-6 跑法、体力和路线

- `domain/race_mechanics.py` 提供版本化、必填公式回调，四种跑法目标区间取自策划；四种节奏、四种超车结果和额外体力消耗统一传给引擎。
- 每个 checkpoint 路线读取同一份状态副本，避免前一匹马更新进度后影响后一匹马的判断。
- 路线公式获得当前 lane/block/overtake/pace 技能修正。具体距离阈值、堵塞损失、速度/体力/毅力公式没有默认数值，必须另行审批后注入。
- 完全相同进度用固定 seed 的顺序破局，结果记录原因；不使用马匹 ID 决定同分胜负。

## P8-7 赛事生命周期

- `CompetitionService`：管理员内部创建接口、报名开放、报名及退款、截止冻结快照、开赛、取消赛事和限量 tick。
- 状态日志：DRAFT → REGISTRATION → LOCKED → RUNNING → FINISHED；开赛前可 CANCELLED。
- 报名费、Entry 和马匹 reservation 在调用者事务中保存。报名即锁定培养、繁育、改名、退役、拍卖和技能修改，采用比截止才锁定更严格的 reservation，防止跨系统竞争。
- 报名要求成年、六技能已补定、选中相性已补定；D 相性允许并提示。不猜报名费、退款比例或奖金。
- 截止保存五维、成长、相性、技能、跑法、状态及 NPC 数据。开赛只读快照。
- 结果、奖金账本、每匹战绩、解锁和 FINISHED 在一个 savepoint 中完成。模拟异常不发奖，回到 LOCKED；同 seed 可重试，FINISHED 不再次发奖。
- 同玩家多匹获奖马先汇总，再以 race/player 唯一引用写现有 ledger。
- Core 的既有到期检查入口可显式装配 `competition_options` 后调用 tick；默认空配置不扫描或模拟赛事。Worker 不持有游戏数据库。
- `/赛程`、`/比赛详情`、`/报名`、`/取消报名`、`/观赛`、`/赛果` 已接现有 Reply/outbox 路由。空赛程明确未开放；没有新增真实群广播。

## P8-8 战绩与分析

- 持久化每 race/horse 的名次、奖金、season_id、首尾体力、技能表现、超车/堵塞事件和确定性分析。
- `/战绩 马名`、`/排行榜 赛马 [奖金|胜场]`；默认财富榜保持原行为。
- 胜率、前三和总奖金从不可重复的战绩记录聚合，避免第二份计数器不同步。积分、成就奖励及赛马世界动态待规则确认，未启用。
- 观赛只读已保存结果，最多输出七条关键事件；不重新模拟。分析只引用确实发生的事件，不编造属性因果。
- `RaceTodoProvider` 和 `/今日` 只显示数据库中实际存在的公开赛事。未开放赛马不加入玩法目录或首次提示。

## P8-9 遗传与拍卖

- `AffinityInheritancePolicy` 要求完整父母等级概率矩阵、变异概率/矩阵与独立版本；无默认概率。
- 繁育时生成并保存亲本、结果、变异、seed 引用，接生时幂等落库，不按新版本重算旧怀孕记录。
- 未含 P8 相性快照的历史幼驹维持 U，不补抽。
- 血统显示已保存的相性结果和独立版本。拍卖资产快照保存相性、技能及战绩摘要，展示时不读取实时培养数值。
- 公共 horse row 锁串行化报名/拍卖/技能与养成操作，赛事锁和拍卖托管互斥。

## P8-10 NPC 和离线工具

- NPC 模板包含公开难度、固定五维区间、成长、全相性、跑法、六技能或明确技能池/等级范围。固定 seed 生成，无按玩家强度隐藏加成。
- NPC 不插入玩家资产表，不领奖金，不占玩家战绩；占据真实名次，不把 NPC 奖金转给下一名。
- 只补到赛事 min_horses；具体模板、难度池、补位目标待提供，默认关闭。
- `domain/race_balance.py::simulate_balance` 提供 1～10000 次纯内存离线工具，输出胜率、前三率、平均排名/体力、超车/堵塞和技能统计。导入不会自动运行，禁止接正式平台压测。
