# 铃露回复样式预览（1000字紧凑版，待确认）

日期：2026-09-28。已确认样式已在本地代码按 **P7.5** 落实，未部署服务器。示例仍作为排版参考，具体动态内容以真实状态为准。

示例中的玩家、价格、数量、时间均为排版示意，不代表真实账户或行情。代码块内为拟发送正文；标题和说明不发送。

## 1. 全局约定与确认方式

- 平台硬上限：整条正文1000字、最多10次换行，即最多11个逻辑行。常规目标：正文900字以内、最多10行（9次换行），空白行也计入。
- 手机或网页自动折行取决于字体和屏幕宽度，不能保证实际视觉只有 10 行。
- 不显示时间戳、操作编号、个体动物编号；马匹、拍卖等确需定位的编号只放详情。
- 等级旁显示升级费用；满级显示“已满级”。牧场费用包含现有税费。
- 商品数量使用 `×`；信息用 `｜`，可用命令之间使用 ASCII ` | `。短条目同一行放2项，复杂状态一项一行；不靠大段空格对齐中英文与Emoji。
- 金额最多两位小数；生产进度条固定 6 格；面板时间统一如 `2.4h`，临近到期如 `8分钟`。
- 交易成功保留商品、数量、费用和余额；失败保留原因、缺额及可执行指令。
- 玩家主动回复保留原消息的原生引用；公告不引用玩家。
- 本地P7.5已接入 `/库存`、`/农田详情`、`/配方 名称`、`/帮助 模块` 和统一 `/回复页 页码`；预览中早期“模块命令＋页码”草案没有逐项接入，实际翻页统一使用 `/回复页`。服务器尚未部署这些变更。
- 不通过静默截断隐藏库存、交易、配方或马匹；字数或换行任一超限，都按语义分页或改为摘要加详情。没有已确认的单行独立字符上限，不设置虚构的每行100字限制。
- 字数预算包含标题、空格、换行、命令、页码、首次提示及重试追加空格；实际平台字符计数方式尚未独立核验，实现时保守处理Unicode码点和UTF-16计数。
- 尽量利用行内空间，但不强行填满1000字；长用户名、商品名和数值须重新计算预算，手机自动折行仍可能超过10个视觉行。

已确认：尽可能不分页；动物、植物文字前加Emoji；马匹属性文字前加Emoji；牧场A并保留心形；农场A。本文其余细节仍供审阅。

### 尽可能不分页（已确认）

1. 默认一条消息展示，能放下时不出现页码或翻页命令。
2. 利用完整字数预算，短条目每行2–3项；列表长时进一步横向合并，不能固定每页5条而提前分页。
3. 同类动物共享进度；作物按种类和成熟批次聚合，减少重复条目。
4. 常规以900字/10行为目标；优先不分页时可利用剩余空间至1000字/10次换行，附加提示和发送重试空格仍计入总预算。
5. 只有压缩后仍超过任一硬上限，才提供必要分页或独立详情；不截断数据，不自动连发多页，不使用“回复1/2”。
6. 本文示例均能放入一条回复，因此不展示页码；实际超限时才添加页码和翻页入口。

### 增产概率（已确认）

- 统一名称为“增产概率”，用于本次取货的产量基数增量判定，不等于生产速度或固定产量倍率。
- 每只闪光动物提供5%；精饲料在对应动物组有效喂食周期内提供20%，两者进入同一概率池相加。
- 每类动物分别计算：增产概率＝闪光动物数量×5%＋精饲料加成（有效时20%，否则0%）。同一有效周期重复使用精饲料不叠加额外20%。
- 概率的整数倍100%必定触发对应次数，剩余概率再判定一次；每次触发使本次产量基数+1，不永久改变基础基数1。例如105%必定+1，再有5%概率额外+1。
- 牧场页面倒数第二行统一汇总，最后一行仍为可用指令。即使无闪光动物，使用精饲料也显示增产概率20%。
- 示例中🐔鸡有1只闪光且精料中，所以25%；🐑羊有1只闪光但未用精料，所以5%；🐄牛普通且未用精料，所以0%。
- P7.5新批次已以本规则替代精饲料固定产量倍率；旧完成批次保留原快照，新批次不叠加旧1.15倍率。
